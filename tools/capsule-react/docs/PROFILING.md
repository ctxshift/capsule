# React/Yoga conversion measurements

The 2026-10-12 Windows spike keeps the existing 20,000,000 fuel/update,
200,000,000 SDK initialization, QuickJS 4 MiB heap/128 KiB stack, Wasm 8 MiB,
128 nodes, 24 depth, 256 commands, 64 KiB packet and 128 input queue limits.
No React, QuickJS, Wasmtime or quota upgrade was used. Fuel measures Wasm guest
instructions; native Yoga/TMP CPU is separately measured and is outside fuel.

## Reproducible fuel workload

`YogaFuelCases.cs` in `tools/capsule-wasmtime-tests` runs exactly 128 sequential
Settings open/close updates against the typed window fixture. `cabi` uses the
actual native C ABI with a second initialized guest left idle. `control` uses
the managed Wasmtime API with the same carrier, SDK, bundle and Cranelift Speed
configuration. Both report identical fuel on each update. `profile` substitutes
the SDK generated by `bun run --cwd tools/capsule-react profile` and reports fuel
at explicit phase markers through a diagnostic import. Missing instrumentation
anchors fail explicitly. Marker-free controls determine the acceptance result.

From the repository root after building the experimental SDK and TSX package:

```powershell
dotnet run --project tools/capsule-wasmtime-tests -- --yoga-fuel cabi
dotnet run --project tools/capsule-wasmtime-tests -- --yoga-fuel control
bun run --cwd tools/capsule-react profile
dotnet run --project tools/capsule-wasmtime-tests -- --yoga-fuel profile
```

Append `-mixed` to each variant for 128 inputs comprising 16 repetitions of
System open/focus, Settings open, brightness, selection, System focus, Log Out
dialog, Escape and Settings close. Alternate brightness extremes and select
values. This checks fresh callbacks, keyed window order and close/reopen state.
`tests/optimization-parity.test.ts` compares approved/current SDKs and fresh TSX bundle
paths, requiring byte-identical packets and handles for startup and all 128 mixed
inputs. Renderer tests additionally retain Unicode, mixed/fixed layout and quota
coverage; approved SDK wire goldens remain unchanged.

| Settings open/close, 128 samples | P50 fuel | P95 fuel | Maximum fuel |
| --- | ---: | ---: | ---: |
| Original uninstrumented | 6,439,930 | 18,443,989 | 18,977,050 |

Final peak reduction is 19.9%; remaining fuel at the observed worst update is
4,798,051 (24%). This is measured headroom for these workloads, not a guarantee
against every future guest workload or GC schedule. Final mixed controls match
per update: P50 8,756,630; P95 9,980,773; maximum 15,055,849. Instrumented mixed
maximum is 15,427,213. Adjacent diagnostic marker pairs cost approximately
17,090 fuel; instrumented maxima include overhead and are reported separately.

## Attribution and limitations

Original worst opening update, round 18 in the paired instrumented run:

| Measured phase | Fuel |
| --- | ---: |
| Event handler | 97,831 |
| React reconciliation after handler | 5,549,785 |
| Snapshot walk/allocation phase | 7,856,626 |
| Diff and serialization | 5,325,699 |
| Guest-side submit import call | 17,906 |

The ordinary opening snapshot walk costs about 2.40M, while this peak costs
7.86M with the same output. The extra work lies inside an allocation-heavy
snapshot phase. GC involvement is inferred from that allocation-correlated
spike and differential improvements; QuickJS GC events/counters were not directly
measured. It must not be presented as direct GC-event attribution. React and
event costs are explicitly marked; observations/effects/scheduler are separately
logged. Native import wall-time and Yoga calculation CPU do not become Wasm fuel.

## Native host bounds and integration

Native Yoga 3.2.1 uses immutable host snapshots and captured Georgia metrics;
the worker retains no pointers into guest memory. The native ABI rejects nonfinite
styles and enforces 128 nodes, depth 24 and bounded measurement callbacks. The
bounded 128-node proof uses 5 warmups plus 64 samples: native calculation P50
0.1029 ms, P95 0.1268 ms, max 0.1514 ms; total host call P50 0.104 ms, P95
0.1279 ms, max 0.2934 ms. Maximum text callbacks 127, roots return to zero.
Total call timing includes validation/style application/measurement, not just
`CalculateLayout`. These are observed wall-time distributions, not preemptive
instruction deadlines for native callbacks.

The independent two-real-guest coordinator proof keeps guest B unacknowledged
while guest A completes 64 updates; rejects foreign roots and stale/rejected
revisions, runs 200 create/unload lifetimes and returns to zero roots. Warm 60
samples: guest P50/P95/max 1.2246/2.1737/2.7894 ms; coordinator
0.066/0.1068/0.115 ms; native Yoga 0.041/0.0733/0.0792 ms. Idle transactions
skip Yoga and the versioned async scheduler does zero work when no deadline/input
is ready. The Player reports worker, main apply and queue-to-visible latency
separately.

This remains a scoped workshop prototype: the workshop has one addon and a
guest-local coordinator. Shared multi-addon batching is proven by the standalone
coordinator harness, not integrated into the production game carrier. Actual
IL2CPP captures and native EventSystem interactions are required alongside these
measurements. An independent visual and functional approval is still necessary.
